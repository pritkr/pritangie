# 011 — Scope every `transition-all` to the properties that actually change

- **Status**: TODO

**Depends on**: plan 010 (provides the `ease-drawer` utility used in step 9).

## Problem

`transition: all` animates unintended properties off-GPU — always a finding
(AUDIT.md §5). The repo has 11 `transition-all` sites; two of them
(`Header.astro:85`, `Button.astro:9`) animate layout properties and are owned by
plan 012. The remaining nine transition `all` on high-frequency hover targets
(nav-adjacent social icons, every card link, the back-to-top reveal):

```astro
<!-- src/components/Hero.astro:57 — current -->
class="transition-all duration-200 hover:translate-y-[2px]"
```

Only one of these elements even changes more than one property; the rest
animate `box-shadow` alone while the transition offers to tween everything.

One real bug lurks in `BackToTop.astro`: its JS toggles `opacity-0` and
`translate-y-2` (Tailwind v4 translate utilities set the **`translate`
property**, not `transform`) — so the transition must cover `translate`
specifically.

Also: `src/pages/404.astro:31` has `hover:bg-[var(--yellow)]` with **no
transition at all** — the highlight snaps on.

## Target

Nine edits. Each `oldString` is a substring of the `class`/`class:list`
attribute — keep every other class untouched.

| # | File:line | Replace | With |
|---|-----------|---------|------|
| 1 | `src/components/Hero.astro:57` | `transition-all duration-200` | `transition-transform duration-200` |
| 2 | `src/components/Footer.astro:28` | `transition-all duration-200` | `transition-transform duration-200` |
| 3 | `src/components/RecentBlog.astro:32` | `transition-all duration-200` | `transition-shadow duration-200` |
| 4 | `src/pages/blog.astro:37` | `transition-all duration-200` | `transition-shadow duration-200` |
| 5 | `src/components/MarkdownPost.astro:58` | `transition-all duration-200` | `transition-shadow duration-200` |
| 6 | `src/components/MarkdownPost.astro:64` | `transition-all duration-200` | `transition-shadow duration-200` |
| 7 | `src/components/Works.astro:131` | `transition-all duration-200` | `transition-shadow duration-200` |
| 8 | `src/components/BackToTop.astro:7` | `transition-all duration-200` | `transition-[opacity,translate] duration-200` |
| 9 | `src/components/Header.astro:101` | `transition-all duration-300` | `transition-transform duration-300 ease-drawer` |

Why each choice:

- 1, 2: only `hover:translate-y-*` changes → Tailwind translate utilities emit
  `translate: var(--tw-translate-x) var(--tw-translate-y)`; `transition-transform`
  covers `transform, translate, scale, rotate` (confirmed in built CSS), so it
  is correct here.
- 3–7: hover changes `box-shadow` only → `transition-shadow`.
- 8: JS toggles `opacity-0` (opacity) and `translate-y-2` (translate property),
  hover adds `-translate-y-1` (translate) → `transition-[opacity,translate]`.
  Do NOT write `transition-[opacity,transform]` — `transform` would miss
  Tailwind's `translate` property and the reveal would snap.
- 9: full-screen drawer slide (translate) + needs the plan-010 drawer curve.
  `ease-drawer` is a Tailwind utility generated by the `--ease-drawer` theme key
  from plan 010.
